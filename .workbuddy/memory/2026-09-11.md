## 修复 xlsx 的三处格式缺陷

用户发现 EXIF 时间列显示为 `45577.3564930556`（Excel 序列号）。排查出三个 bug，均已修复：

1. **日期格式码错误** —— `build_selected_lab_visits_workbook_streaming.py` 曾用
   `cell.number_format = DATETIME_FORMAT.lower()`，把 Python `strptime` 格式串
   `"%y-%m-%d %h:%m:%s"` 当成 Excel 格式码。Excel 不认 `%`，单元格退化为序列号显示。
   已改为常量 `EXCEL_DATETIME_FORMAT = "yyyy-mm-dd hh:mm:ss"`。
   **教训：strptime 格式串 ≠ Excel number_format，两者绝不能互相复用。**
2. **审计表日期列索引漏项** —— `AUDIT_DATE_COLUMNS` 原为 `{2,9,10}`，漏了住院2 的
   `住院2锚点申请时间`/`住院2最晚申请时间`，导致这两列以字符串落盘。
   已补为 `{2,9,10,16,17}`。
3. **列宽/冻结窗格全部丢失** —— `Workbook(write_only=True)` 根本不输出 `<cols>`，
   也吞掉 `freeze_panes` 与 `showGridLines`，脚本里写的列宽从未生效
   （原文件 XML 中 `<cols>` 块完全不存在，全列默认宽 13）。
   改用「保存后把 `<cols>`/`<sheetViews>` 拼进 sheet XML 再重打包」，保持恒定内存
   （23 万行用普通模式会 OOM，机器仅 5.5 GB 可用）。新增 `patch_sheet_xml` /
   `build_cols_xml` / `build_sheet_views_xml` / `verify_layout` / `verify_date_cells`。
   Node 版 `build_selected_lab_visits_workbook.mjs` 同样漏了审计表 P/Q 日期列，已补。

**踩坑记录**：`openpyxl` 读回时，`<col min="5" max="7">` 这样的区间只会挂在首字母 `E` 下，
用 `ws.column_dimensions['F']` 取会拿不到值（回落默认 13）。校验列宽必须按
`dimension.min <= idx <= dimension.max` 遍历匹配，否则会误判成「列宽丢失」。

**结果**：数据逐格未变（只改格式），已用备份 `*.xlsx.bak_bad_numfmt` 对比确认。
