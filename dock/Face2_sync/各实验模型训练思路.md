# E0B：Global ResNet18 对照组 vs NYHA 患者二分类实验训练实现思路

## 1. 实验目标、边界与命名

### 1.1 要解决的任务

E0B 是一个独立于原 E0 三分类任务的二分类实验。输入是一张经既有全局人脸预处理得到的 224×224 RGB 面部图像；输出是该图像属于以下哪一类的概率与预测类别：

| 二分类编码 | 名称 | 对应原始三分类标签 | 对应 NYHA 范围 |
|---:|---|---|---|
| 0 | Control / Normal（无病正常对照） | `label_3class=0` | `NYHA=0` |
| 1 | Patient（患者） | `label_3class=1` 或 `2` | `NYHA=I–IV` |

这里的 Control 是额外设置的无病正常对照，**不是“NYHA 0 级心衰”**。该实验评估的是“对照与患者的图像可分性”，不能据此声称模型可诊断心力衰竭、预测 NYHA 等级或替代临床评估。

### 1.2 与 E0 三分类的关系

E0B 保留原 E0 的固定 500 例数据范围、固定患者级五折划分、全局人脸图像、ResNet18 主干和主要优化策略；改变的是最后的监督任务：把原 `Normal / Mild / Severe` 三类合并为 `Control / Patient` 两类，并把分类头改为 2 输出。

为了避免污染原 E0，E0B 不修改原始划分 CSV、原 E0 三分类 Dataset 或原 E0 结果。二分类标签只在运行时由专用 Dataset 动态生成。

### 1.3 代码位置与职责划分

| 层级 | 文件 | 职责 |
|---|---|---|
| 一键编排入口 | `scripts/run/run_e0b_global_resnet18_control_patient_binary_5fold.py` | 依次启动训练与汇总，保证正式运行不会遗漏 OOF 汇总。 |
| 五折训练入口 | `scripts/train/train_e0b_global_resnet18_control_patient_binary_5fold.py` | 训练每个 fold、保存最佳模型、生成逐折验证预测。 |
| 汇总评估入口 | `scripts/evaluate/summarize_e0b_global_resnet18_control_patient_binary_5fold.py` | 检查 OOF 完整性、汇总五折预测、计算最终指标并输出报告。 |
| 二分类 Dataset | `datasets/control_patient_binary_dataset.py` | 读取固定 CSV、执行 3 类到 2 类映射、加载图像及保留追溯元数据。 |
| 指标模块 | `metrics/binary_classification_metrics.py` | 对二分类概率进行校验并计算 AUC、F1 等指标。 |
| 训练前审计 | `utils/e0b_binary_audit.py` | 在训练前验证划分、标签、图像和患者组泄漏情况。 |
| 实验配置 | `config/train/e0b_global_resnet18_control_patient_binary_5fold.yaml` | 固定数据、模型和训练超参数。 |
| 单元测试 | `tests/test_e0b_control_patient_binary.py` | 保护标签映射、概率约束、指标和类别权重计算。 |

通用复用组件包括 `datasets/nyha_3class_face_dataset.py` 中的图像变换、`models/nyha_backbone_factory.py` 和 `models/resnet_nyha_3class.py` 中的模型构建、`losses/classification_losses.py` 中的类别权重，以及 `utils/experiment_utils.py` 中的随机种子、YAML 和日志工具。

## 2. 从一键运行入口开始的完整调用链

### 2.1 一键入口的职责

`run_e0b_global_resnet18_control_patient_binary_5fold.py` 接收两个必需参数：`--config` 和 `--output-dir`。相对路径先相对于项目根目录 `E:\projects\face2` 解析，再使用当前 Python 解释器（`sys.executable`）以子进程依次执行：

1. `scripts/train/train_e0b_global_resnet18_control_patient_binary_5fold.py --config <config> --output-dir <output-dir>`；
2. 上一步正常退出后，执行 `scripts/evaluate/summarize_e0b_global_resnet18_control_patient_binary_5fold.py --experiment-dir <output-dir>`；
3. 只有训练和汇总都成功，才打印 `EXPERIMENT_COMPLETED=<output-dir>`。

两个 `subprocess.run` 都使用 `check=True`。因此训练失败时不会错误地把不完整结果送去汇总；汇总的 OOF 校验失败时也不会打印“已完成”。一键入口本身不重写配置、不改变类别定义，仅负责顺序与失败传播。

推荐正式命令如下（在项目根目录执行）：

```powershell
python scripts\run\run_e0b_global_resnet18_control_patient_binary_5fold.py `
  --config config\train\e0b_global_resnet18_control_patient_binary_5fold.yaml `
  --output-dir experiments\500Data\E0B_Global_ResNet18_ControlVsPatient_Binary_5fold_GPU
```

若要保证使用指定 Conda 环境，不应依赖当前终端是否激活，可把命令首部替换为：

```powershell
E:\resarch\Anaconda3\envs\face_heart\python.exe scripts\run\run_e0b_global_resnet18_control_patient_binary_5fold.py --config config\train\e0b_global_resnet18_control_patient_binary_5fold.yaml --output-dir experiments\500Data\E0B_Global_ResNet18_ControlVsPatient_Binary_5fold_GPU
```

前提是该解释器内的 PyTorch 已正确识别 CUDA；训练代码会选择 `cuda`（可用时）或回退至 `cpu`，没有“强制 GPU”开关。

### 2.2 训练入口的运行顺序

训练入口的主流程是：

1. 读取 YAML；仅在隔离 smoke run 中允许 `--epochs` 覆盖最大 epoch。
2. 强制检查任务声明：`task.type` 必须是 `binary_control_vs_patient`、`task.num_classes` 与 `model.num_classes` 必须是 2、优化器必须为 AdamW、模型选择指标必须为 `macro_auc`。不符合协议则立即报错。
3. 创建输出目录，初始化同时写入终端和 `experiment.log` 的日志。
4. 写入不可变的 `config_snapshot.yaml` 和 `environment.json`。环境文件记录 Python、操作系统、Torch/Torchvision 版本、CUDA 可用性、CUDA 版本、GPU 名称及 Git commit（可取得时）。
5. 在任何模型训练之前运行 `audit_fixed_splits`；审计失败就停止，避免产生不可信结果。
6. 以 seed 2026 固定 Python、NumPy、PyTorch CPU/CUDA 的随机种子，并设置 `cudnn.deterministic=True`、`cudnn.benchmark=False`。
7. 默认依次训练 `fold=0,1,2,3,4`。`--fold N` 可重复传入，仅用于指定折的开发/烟雾测试；它不会自动替代完整五折正式结果。
8. 全部指定 fold 完成后，写入 `run_finished_at.txt` 并打印 `EXPERIMENT_DIR=<output-dir>`。

## 3. 数据来源、固定划分与二分类标签

### 3.1 输入数据

配置固定以下路径，所有相对路径均以项目根目录为基准：

| 对象 | 路径或模式 | 用途 |
|---|---|---|
| 五折划分目录 | `data/processed/splits_500` | 训练/验证样本及患者组信息的唯一来源。 |
| 每折训练表 | `fold_{fold}_train.csv` | fold 0–4 对应 5 个训练 CSV。 |
| 每折验证表 | `fold_{fold}_val.csv` | fold 0–4 对应 5 个验证 CSV；五张表拼接后构成 OOF。 |
| 图像根目录 | `data/processed/global_face/preprocess_ablation/hybrid_imagenet_meanbg/images` | 每个 ID 对应一张 `{ID}.png` 全局人脸图像。 |

CSV 至少必须具有 `ID`、`patient_group_id`、`NYHA`、`label_3class`、`fold` 列。`ID` 与 `patient_group_id` 读取为字符串，避免诸如前导零或科学计数法导致的样本标识变化。

### 3.2 标签转换规则

`map_three_class_to_binary` 是唯一的转换函数。它先把输入安全转换为整数，再严格执行：

```text
label_3class = 0  -> binary_label = 0  (Control)
label_3class = 1  -> binary_label = 1  (Patient)
label_3class = 2  -> binary_label = 1  (Patient)
其他值           -> 抛出 ValueError，停止运行
```

转换发生在 `ControlPatientFaceDataset` 构造时，保存为内存中的 `self.labels`；不向 `fold_*.csv` 写入新列，也不重新划分数据。每个取样项返回图像张量、二分类标签、样本 ID、患者组 ID、原始 NYHA、原始三分类编码/名称、图像绝对路径和 fold。这样汇总阶段可追踪任一预测来自哪个原始组别与哪张图像。

### 3.3 正式运行前的数据审计

`audit_fixed_splits(config, output_dir)` 对每一折的 train/val CSV 执行以下不可变检查：

1. 所有必要列存在。
2. 原始 `NYHA` 与 `label_3class` 一致：`0→0`，`1/2→1`，`3/4→2`。不接受缺失或其他 NYHA/三分类值。
3. 由三分类标签映射出的二分类标签合法。
4. 同一 fold 的训练、验证集 `patient_group_id` 无交集，防止同一患者组泄漏至验证集。
5. 每个训练集和验证集都同时含 Control 与 Patient 两类，确保二分类加权交叉熵和 AUC 有定义。
6. 验证样本的 `{ID}.png` 必须真实存在；任意缺图会停止训练。
7. 合并五个验证集后，500 个 OOF 样本 ID 不重复。
8. 同一 `patient_group_id` 不能出现互相冲突的二分类标签。冲突明细总会先写入 `binary_label_conflicts.csv`，若存在任一冲突则停止正式训练。

审计成功时写出 `fold_binary_distribution.csv` 和 `data_audit_report.md`。此次已完成实验的审计结果为：500 个 OOF 样本、483 个患者组、115 个 Control、385 个 Patient，且五折无验证 ID 重复、无训练/验证患者组泄漏、无二分类患者组冲突、无缺失图像。

## 4. 图像处理、Dataset 与 DataLoader

### 4.1 图像读取和变换

Dataset 用 Pillow 打开 `{ID}.png`，统一转换为 RGB。变换复用 E0 的 `build_transforms`：

| 阶段 | 处理顺序 |
|---|---|
| Train | `Resize((224,224))` → `RandomHorizontalFlip(p=0.5)` → `ToTensor()` → ImageNet `Normalize` |
| Validation | `Resize((224,224))` → `ToTensor()` → 相同的 ImageNet `Normalize` |

ImageNet 标准化均值为 `[0.485, 0.456, 0.406]`，标准差为 `[0.229, 0.224, 0.225]`。验证阶段无随机翻转、无颜色扰动、无随机裁剪；因此同一个 checkpoint 的验证预测是确定性的。

### 4.2 DataLoader 与可重复性

每折独立构造 Train/Validation DataLoader。训练 loader 使用 `shuffle=True`，验证 loader 使用 `shuffle=False`；batch size 是 16。每个 loader 使用显式 `torch.Generator` 和 `seed_worker`：训练折 seed 为 `2026 + fold`，验证折 seed 为 `2026 + 1000 + fold`。当 `num_workers>0` 时，worker 也会根据 PyTorch 初始种子同步 Python/NumPy 随机状态。

当前配置是 `num_workers=0`、`pin_memory=false`、`persistent_workers=false`，因此不会产生额外数据加载子进程。若迁移到服务器，可以在确认内存和 I/O 后调整 `num_workers`、`pin_memory`，但必须在新实验目录保存新的配置快照，不能把不同设置与现有 E0B 结果混用。

## 5. 模型、损失函数和优化

### 5.1 模型结构

模型经 `build_nyha_classification_model("resnet18", num_classes=2, pretrained="imagenet", freeze_backbone=False)` 构造：

1. 加载 torchvision ResNet18 的 ImageNet-1K 预训练权重；
2. 将原始 `fc` 替换为 `Linear(512, 2)`，直接输出两个未归一化 logits；
3. 全部参数 `requires_grad=True`，即全量微调，并非冻结主干后只训练分类头；
4. 训练入口额外断言 `model.fc.out_features == 2`，避免意外运行成三分类头。

正式结果中模型参数量为 11,177,538，且全部可训练。

### 5.2 类别不平衡处理

由于 500 个样本中 Control:Patient 为 115:385，损失函数使用**当前训练折单独计算**的类别加权交叉熵，绝不使用验证折或全体数据计算权重。权重公式为：

```text
weight[c] = N_train / (2 × count_train[c])
```

每一折训练集数量为 Control 92、Patient 308，故各折实际权重为：

```text
weight_control = 400 / (2 × 92)  = 2.173913
weight_patient = 400 / (2 × 308) = 0.649351
```

训练时 `torch.nn.CrossEntropyLoss(weight=weights)` 接收 logits 与整数二分类标签。这里没有 label smoothing，也没有 sampler 重采样；类别平衡只通过 loss 权重实现。

### 5.3 优化与早停

每折重新创建一个模型、损失函数和 AdamW 优化器，折之间不存在模型参数或 optimizer state 继承。固定配置为：

| 项目 | 值 |
|---|---|
| Optimizer | AdamW |
| Learning rate | `1e-4` |
| Weight decay | `1e-4` |
| Batch size | 16 |
| 最大 epoch | 50 |
| 早停 patience | 10 个连续未提升 epoch |
| 保存/监控指标 | 验证集 `macro_auc` |
| 最大化方向 | 越大越好，严格使用 `auc > best_auc` 作为提升条件 |
| AMP | 配置为 `false`，代码未使用 autocast/GradScaler |

单个 epoch 的流程为：对训练 mini-batch 前向计算 logits → 加权交叉熵 → `optimizer.zero_grad(set_to_none=True)` → 反向传播 → `optimizer.step()`；随后立即在该折完整验证集上推理并计算 `macro_auc`。当 AUC 刷新时保存 `checkpoints/best_macro_auc.pth`；无论是否刷新都覆盖保存 `checkpoints/last.pth`。耐心耗尽后结束该折。

每折结束后会**重新加载最佳 AUC checkpoint**，而不是使用最后一个 epoch 的参数，再对该折完整验证集生成最终 `val_predictions.csv` 与指标。因此 OOF 预测都来自每折验证 macro-AUC 最好的模型。

## 6. 验证概率、指标和最佳模型选择

### 6.1 预测定义

模型输出 `[logit_normal, logit_patient]`，通过 `softmax(dim=1)` 转为 `[prob_normal, prob_patient]`。预测类别为概率最大值的索引：

```text
pred_class = argmax([prob_normal, prob_patient])
```

不进行验证集阈值搜索、手动阈值调整、概率校准或测试时增强。二分类 ROC-AUC 使用正类 Patient 概率 `prob_patient`，而不是 hard label。

### 6.2 指标模块的约束和输出

`compute_binary_metrics(y_true, y_prob)` 在计算前要求：标签是一维且非空、只取 0/1；概率形状为 `[N,2]`；所有概率有限且在 `[0,1]`；每行概率和在容差 `1e-5` 内等于 1。违反任一条件立即抛错，避免将 logits、未归一化分数或多分类概率误用于二分类指标。

通过验证后输出：

| 指标 | 计算方式/用途 |
|---|---|
| `macro_auc` | `roc_auc_score(y_true, prob_patient)`；每折挑选 checkpoint 的唯一指标。 |
| `accuracy` | `argmax` hard prediction 的总体正确率。 |
| `macro_precision` | 两类 precision 的宏平均。 |
| `macro_recall` | 两类 recall 的宏平均。 |
| `macro_f1` | 两类 F1 的宏平均。 |
| `balanced_accuracy` | 两类 recall 的平均，用于减轻多数 Patient 类的影响。 |
| `confusion_matrix` | 固定标签顺序 `[0=Control, 1=Patient]` 的 2×2 矩阵。 |

因此不应只报告 Accuracy；在患者占多数时，应联合看 Macro-F1、Balanced Accuracy、混淆矩阵和 AUC。

## 7. 单折产物、OOF 汇总和二次完整性检查

### 7.1 每折输出

每个 `fold_<k>` 目录包含：

| 文件 | 内容 |
|---|---|
| `checkpoints/best_macro_auc.pth` | 验证 macro-AUC 最佳模型的权重、epoch、最佳 AUC 和配置。 |
| `checkpoints/last.pth` | 最后完成 epoch 的模型状态。 |
| `training_history.csv` | 每个 epoch 的训练损失与验证六项标量指标。 |
| `val_predictions.csv` | 最佳 checkpoint 的逐样本验证预测与完整追溯信息。 |
| `metrics.csv` | 本折最佳 epoch、运行秒数、训练类别数/权重、参数量和验证指标。 |
| `confusion_matrix.csv` | 本折 2×2 混淆矩阵。 |
| `training_parameters.json` | 训练样本数、权重、总参数量和可训练参数量。 |

逐样本预测记录包括 `sample_id`、`patient_group_id`、`fold`、原始 NYHA/三分类信息、二分类真值、两个 logits、两个 softmax 概率、`pred_class`、正确与否、图像路径、选中 epoch 与 checkpoint 路径。它足以复查任一 OOF 样本，不依赖训练时内存对象。

### 7.2 汇总入口的流程

训练成功后，一键入口调用汇总脚本。汇总脚本首先读取输出目录的 `config_snapshot.yaml`，然后：

1. 读取五个 `fold_<k>/val_predictions.csv` 与 `metrics.csv`；
2. 重新读取固定的五个验证 CSV，独立计算每个 `sample_id` 期望的二分类标签；
3. 合并预测为 OOF 表，并检查所有必需列存在、行数等于期望样本数、ID 无重复、ID 集合与固定验证划分完全一致；
4. 检查二分类标签范围、概率范围/每行和、`pred_class==argmax(probabilities)`、fold 覆盖为 0–4；
5. 再次检查预测表中的原始三分类标签映射与原固定 CSV 的二分类真值均一致；
6. 对全部 500 个 OOF 样本的合并预测一次性计算最终指标和混淆矩阵，而不是简单平均各折 AUC；
7. 依据原始三分类组 Normal/Mild/Severe 分别汇总 `prob_patient` 的样本数、均值、标准差、分位数、最小/最大值，作为描述性分析。

这层二次校验可防止“某折遗漏、重复拼接、标签错位、概率列并非 softmax 概率”等问题混入正式结论。

完整实验目录为 `experiments/500Data/E0B_Global_ResNet18_ControlVsPatient_Binary_5fold_GPU`。除五个 fold 目录外，根目录还会形成：

## 9. 复现、修改和扩展时必须保持的原则

1. **固定划分优先。** 若目标是与 E0B 可比，必须继续使用 `splits_500/fold_{0..4}_{train,val}.csv`，不能重新随机分层、随机抽样或把训练/验证表互换。
2. **标签只在运行时映射。** 继续使用 `0→0、1/2→1`；不要为了二分类覆盖原三分类 CSV，也不要把 `NYHA=0` 表述为患者严重程度。
3. **患者组不可泄漏。** 每折 train/val 的 `patient_group_id` 不得交叠；新增数据或新划分必须重新审计。
4. **模型头必须是真正二分类。** `num_classes=2` 且最终 `fc` 输出 2 个 logits；不要使用 3 输出后仅在评估时合并概率，这会改变损失和学习目标。
5. **类别权重只看当前训练折。** 不使用验证集、OOF 或全数据标签计算权重；类别缺失时应该报错而非静默置零。
6. **模型选择与最终 OOF 分开。** 每折用本折验证集 macro-AUC 选 checkpoint；最终性能由五折 OOF 拼接后重新计算。不要把各折 AUC 直接平均后当作唯一的总体指标。
7. **不做未记录的阈值优化。** 当前预测是 softmax argmax；若将来优化阈值、做校准、加入 AMP、改变增强或调整超参数，必须建立新的输出目录并在配置/报告中明确记录，不能覆盖或混同现有结果。
8. **结果解释保持克制。** E0B 的正类是“所有 NYHA I–IV 合并的患者”；它不提供 Mild vs Severe 的区分能力，也不能代替诊断或临床量表。
