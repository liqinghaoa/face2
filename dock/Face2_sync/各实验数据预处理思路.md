# 各实验数据预处理实现思路

本文描述当前项目中已存在的数据预处理和生成式预处理管线。内容以实际代码为准，目的在于让后续开发者或模型能够在**不改变既有数据定义、几何坐标系、mask 含义和审计边界**的前提下复现、扩展或生成新版本数据。

共同原则：不重划分样本、不重写标签、不用标签/NYHA/fold/预测结果参与图像像素计算；任何规则变化都应写入新输出目录，不能覆盖既有实验输入。

## 一、Global Parsing Hybrid + Forehead Repair 黑背景全局人脸预处理

### 1. 程序、配置、输入和输出契约

| 项目 | 实际位置/取值 |
|---|---|
| 主程序 | `preprocessing/build_global_face_parsing_hybrid_foreheadrepair_blackbg_224_png_strict.py` |
| 对齐依赖 | `preprocessing/build_global_face_oval_blackbg_png_simalign_strict.py` |
| 人脸解析依赖 | `preprocessing/build_global_face_parsing_regularmask_blackbg_224_png_strict.py` |
| YAML 配置 | `config/preprocess/global_face_parsing_hybrid_foreheadrepair_blackbg_224_png_strict.yaml` |
| 样本索引 | `data/raw/label_raw.csv` |
| 原始图片 | `data/raw/images`，按 `ID` 匹配常见图片扩展名 |
| 输出根目录 | `data/processed/global_face/global_face_parsing_hybrid_foreheadrepair_blackbg_224_png_strict` |
| 最终图像 | `images/<ID>.png` |
| 图像规格 | 224×224、RGB、`uint8`、PNG、黑背景 |

当前配置的关键参数：Face Detection/FaceMesh 最低置信度 0.5；解析模型为 BiSeNet；解析权重为 `preprocessing/checkpoints/face_parsing/79999_iter.pth`；`final_mask_mode=hybrid`；额部带比例 0.35；头发触发阈值 0.10；候选 envelope 的额部/两侧/下颌扩展比例为 0.18/0.05/0.03；alpha feather 核为 11；默认 `overwrite=false`。

输出 PNG 是普通图像，**不写入** ImageNet mean/std 标准化。ImageNet 标准化仅在 BiSeNet 推理时临时使用；训练 Dataset 仍须自行完成 Tensor 转换和模型所需的标准化。

### 2. 处理总流程

对索引中的每一个 ID，依次执行：

```text
定位原图
  → MediaPipe Face Detection
  → 选择主脸
  → 扩展人脸框内运行 FaceMesh
  → 关键点回映射到原图坐标
  → 原图直接相似变换至 224×224
  → BiSeNet 像素级人脸解析
  → selected semantic mask
  → 规则化 semantic mask
  → candidate envelope
  → hybrid 额部局部修复
  → feather alpha
  → mask 外置黑并保存 PNG
  → 日志、失败记录和 QC 预览
```

索引中的 ID、NYHA、fold、性别等字段可被复制进日志以便追踪，但不会进入人脸检测、对齐、解析、mask 或像素处理公式。

### 3. 主脸选择与原图坐标直接对齐

1. 使用 MediaPipe Face Detection 获取候选检测框，转换为图像像素坐标并裁剪到图片边界。
2. 多脸时采用确定性规则选择主脸：分数与检测框面积正相关、与检测框中心到图像中心的距离负相关；同分时按稳定顺序处理。因此不会随机选择人脸。
3. 在主脸框的基础上扩展裁剪区域：上方 10%、下方 20%、左右各 20%。FaceMesh 在该扩展裁剪图上运行。
4. 从 FaceMesh 取得左眼中心、右眼中心、鼻尖、左右嘴角五个对齐点，同时取得 face oval 点用于完整性检查。关键点缺失、非有限、双眼距离退化或 oval 面积过小，均为失败而非回退。
5. 关键点加回扩展裁剪框左上角偏移，转换为**原始图片坐标**。目标模板中五点的归一化坐标为：左眼 `(0.35, 0.38)`、右眼 `(0.65, 0.38)`、鼻 `(0.50, 0.55)`、左嘴角 `(0.40, 0.72)`、右嘴角 `(0.60, 0.72)`，再乘以 `image_size - 1`。
6. 使用 `cv2.estimateAffinePartial2D(..., LMEDS)` 拟合变换，并显式验证变换矩阵是严格相似变换（旋转 + 等比例缩放 + 平移；不允许 shear 或独立横纵缩放）。
7. 将该矩阵直接作用于**原始 RGB 图像**，使用 `cv2.warpAffine` 生成 224×224 对齐图。这是该管线的重要设计：不对已裁剪图进行最终旋转，因此裁剪边界不会旋转成斜向黑色缺口。
8. 另对全白有效图做同样变换，计算输出顶部 5% 区域的无效比例；超过 0.20 时写入 `top_cut_warning`，但不改变图像、不静默补图。

### 4. BiSeNet 解析与 selected semantic mask

1. 对齐 RGB 被 resize 到解析网络输入尺寸、转换为 `[0,1]`，按 ImageNet mean/std 标准化后输入 BiSeNet。
2. 输出 logits 取 argmax，必要时以最近邻插值回 224×224，得到整数解析标签图。
3. selected semantic mask 仅由下列类别构成：skin、left/right brow、left/right eye、nose、mouth、upper lip、lower lip。hair、ear、neck、cloth、background 不构成 selected semantic 主体。
4. selected mask 像素过少（少于 `max(64, 图像面积×0.0025)`）时直接报 `failed_empty_selected_mask`。
5. 为找到主面部连通区域，内部可使用闭运算和最大连通域，但返回的 selected mask 仍是原始真实语义类别像素，而不是闭运算凭空新增的像素。

### 5. 规则化语义主体与候选 envelope

全局 hybrid 程序会对 selected mask 再做轻量规则化，得到语义主体：

1. 使用 5×5 椭圆核闭运算连接微小间隙；
2. 只保留最大连通域；
3. 对反相区域做连通域分析，仅填充不接触边界且面积不超过 `max(32, 图像面积×0.003)` 的小孔洞；
4. 使用 5×5 Gaussian blur（`sigma=1.0`）后以 127 阈值二值化，减轻轮廓阶梯状锯齿；
5. 规则化结果仍过小时失败。

大面积的额部缺口不会在这里填补，这是有意设计：它们保留给下一步根据遮挡证据做局部 hybrid 修复。

随后从语义主体构造连续的 candidate envelope：根据语义主体包围框向上、左右、下方扩展；用已解析的耳朵限制两侧边界，并用 neck/cloth 的最上方位置限制下边界。最终生成连续椭圆 envelope。它是额部修复的候选区域，不等同于默认 final mask。

### 6. Hybrid final mask 与额部修复规则

模式有 `semantic`、`envelope`、`hybrid` 三种；当前配置使用 `hybrid`：

1. 计算 candidate envelope 内 hair 像素比例；同时计算语义主体顶边在额部带内的锯齿度。
2. hair 比例 `> 0.10` 时触发 hair occlusion；若 `enable_jaggedness_trigger=true` 且锯齿度 `> 0.04`，也可触发 jaggedness 修复。
3. 当前配置显式关闭 jaggedness trigger，所以锯齿度只进入日志，不会单独改变最终 mask。
4. 未触发时，`final_mask = semantic_regularized_mask`。
5. 触发时，只在额部带中进行局部 OR：额部带下界为语义主体高度的前 35%；带上界取 envelope 顶部与语义主体顶部的合理范围，避免因从语义顶部直接开始而制造明显“平顶”。带外仍保留语义主体，不会把整张脸替换为椭圆。
6. final mask 像素少于 `max(64, 图像面积×0.01)` 时失败。

因此，后续实现时不得把该版本简化为“固定椭圆 mask”或“全图 envelope mask”。其准确语义是：**自然语义人脸主体优先，仅在疑似头发遮挡的额部局部使用 envelope 修复。**

### 7. 最终渲染、日志、QC 与验收

1. 计算 final mask 内 hair、neck、cloth、background 的比例；hair 比例超过 0.10 或 0.20 时分别写普通/重度遮挡 warning。
2. final mask 面积比低于 0.35 或高于 0.85 时写 warning，不会自动删除样本。
3. 用 11×11 Gaussian feather 将 binary final mask 变为 alpha；使用 alpha 将对齐 RGB 的 mask 外区域置黑；保存 `images/<ID>.png`。
4. 成功行写入 `logs/preprocess_log.csv`，失败行同时汇总为 `logs/failed_cases.csv`；`logs/parsing_hybrid_summary.csv` 与 `logs/preprocess_summary.txt` 汇总成功率、失败类型、额部修复次数和指标分布。
5. `qc_preview/` 至少覆盖随机成功、semantic-only、forehead-repair、高 hair/cloth/neck 污染、mask 面积异常和典型失败样本。每个预览可展示原图检测框、裁剪图、对齐图、解析图、各阶段 mask overlay 与最终黑背景图。
6. 仅当 `save_intermediates=true` 时保存 `aligned_rgb`、`final_mask`、`selected_semantic_mask`、`semantic_regularized_mask`、`candidate_envelope`、`parsing_label`；默认只需最终 PNG、日志和 QC。

验收时至少检查：每个成功 ID 都有 224×224 RGB PNG；日志状态可解释；mask 外黑背景成立；输出数与成功数一致；失败不被伪装为成功；额部修复仅在日志给出的触发条件下发生。任何参数改动、模型权重改动、解析类别改动或重建方式改动都应视为新预处理版本。

## 二、ROI Masked：基于对齐人脸解析的五区域局部预处理

### 1. 程序、配置、输入和输出契约

| 项目 | 实际位置/取值 |
|---|---|
| 主程序 | `preprocessing/preprocess_global_aligned_face_parsing_roi_dataset_224_canvas.py` |
| 复用的全局逻辑 | 全局对齐、BiSeNet 解析、hybrid final mask 逻辑 |
| YAML 配置 | `config/preprocess/global_aligned_face_parsing_roi_final5_224_canvas.yaml` |
| 固定样本索引 | `data/processed/splits_500/nyha_3class_sex_stratified_group_5fold.csv` |
| 原始图片 | `data/raw/images` |
| 可选全局中间产物 | `global_intermediate_dir` 指定的 aligned RGB、解析标签、selected semantic mask、final face mask |
| 输出根目录 | `data/processed/roi_dataset/global_aligned_face_parsing_roi_final5_224_canvas_500` |
| 原始 ROI | `roi_raw/<roi_type>/<ID>.png` |
| mask ROI | `roi_masked/<roi_type>/<ID>.png` |

固定 ROI 类型及默认 core ROI 都是：`eye_roi`、`lip_roi`、`cheek_roi`、`forehead_roi`、`chin_roi`。输出 canvas 为 224×224，black padding，默认保持纵横比；最小 ROI 宽/高均为 8 像素。输入索引所给的 500 例、标签和 fold 仅用于样本选择与输出追踪，不参与 ROI 像素计算。

### 2. 与全局管线的衔接和中间产物回退

每个样本首先尝试从 `global_intermediate_dir` 同时读取以下四个文件：`aligned_rgb/<ID>.png`、`parsing_label/<ID>.png`、`selected_semantic_mask/<ID>.png`、`final_face_mask/<ID>.png`。四者齐全时直接使用，以保证 ROI 与全局版本共享 224 坐标、解析结果和 final face mask。

若中间产物不完整，ROI 程序会从原图重新执行既有严格流程：人脸检测、FaceMesh、原图坐标相似对齐、BiSeNet 解析、selected semantic mask 和 hybrid final face mask。此时仍应使用与全局版本一致的参数；不能以普通 resize、手工裁剪或不同 face parser 作为无提示替代。`save_intermediates=true` 仅控制 ROI 程序是否将本次使用/重建的中间产物复制到自身输出目录。

### 3. 每个样本的总流程

```text
固定 500 例索引
  → 读取或重建 Global 224-space intermediates
  → 在 224-space 中得到 FaceMesh 点、解析标签、final face mask
  → 分别定义 eye / lip / cheek-pair / forehead / chin ROI 框
  → 检查必需语义和最小尺寸
  → 同一 ROI 框生成 raw 与 masked 两个版本
  → resize/pad 为 224×224
  → 记录 ROI 元数据、污染比例、warning 与成功矩阵
  → 生成 QC 预览和多 ROI 有效 ID 清单
```

所有 ROI 坐标均在对齐后的 224×224 图上定义；不要将这些比例和像素坐标直接搬到未对齐的原图。

### 4. 关键事实：`roi_masked` 的 mask 含义

这是后续实现最容易误解的地方。当前 `roi_target_mask()` 的实际实现**不按各 ROI 的语义类别挖空**。它返回的就是完整的 `final_face_mask`：

```text
roi_masked = aligned_rgb × final_face_mask
然后按该 ROI 的 bbox 裁剪、resize、padding
```

因此：

- `roi_raw`：对齐 RGB 按 ROI 框直接裁剪；
- `roi_masked`：对齐 RGB 先在 global final face mask 外置黑，再按**相同 ROI 框**裁剪；
- ROI 专属解析类别用于定位 ROI、检查是否有效和记录 QC 统计，**不用于在 ROI 内挖掉鼻、嘴、眉、眼等语义像素**。

例如 eye ROI 的 masked 图可能仍包含 final face mask 范围内的眉或少量鼻桥；cheek ROI 的 masked 图不是“仅保留解析为 skin 的像素”。若未来确实需要 ROI-specific semantic mask，应建立明确的新版本，不能把它与当前 `roi_masked` 数据混称。

### 5. 五类 ROI 框的具体定义

| ROI | 框的证据与几何规则 | 必需语义/检查 |
|---|---|---|
| Eye | 眼解析框与 FaceMesh 双眼点框取并集；左右各扩约脸宽 9%，向上约脸高 4.5%、向下约 7%；用眉框约束上边界，并尽量在鼻框前限制下边界；高度控制在约脸高 16%–30%。 | 不强制眼解析像素存在；眼解析不稳时可由关键点定位。QC 检查眼缺失、框过窄、鼻混入、过低或过高。 |
| Lip | mouth、upper lip、lower lip 的解析框与 FaceMesh 唇部点框取并集；横向扩 35%，纵向扩 60%。 | 必须存在 mouth/upper lip/lower lip 类别；QC 检查 mouth/lip 过少、颈衣混入、框过小。 |
| Cheek | 先以 final face mask 得到脸框；纵向位于眼下约 4% 脸高到嘴前约 2% 脸高，并限制在脸高约 35%–70%；左右框分别位于脸宽 8%–37% 和 63%–92%。 | 左右两侧都必须存在足够 skin 像素。QC 检查 skin 过少、背景/嘴/眼混入、单侧过窄和左右不对称。 |
| Forehead | 使用 final face mask 脸框、skin 框、眉解析框与眉关键点框；横向在眉框两侧各扩约脸宽 13%，下边界在眉上方约脸高 1.5%，上边界接近脸框/skin 框顶部；最小高度约脸高 15%。 | 必须包含 skin。QC 检查头发遮挡、背景、skin 过少和额部过小。 |
| Chin | 横向为脸框两侧各缩约脸宽 20%；上边界在嘴/唇框下约脸高 2%，下边界受脸框、skin 框以及 neck/cloth 最上缘限制；必要时使用脸高约 90% 的后备下边界。 | 必须包含 skin。QC 检查嘴/唇、颈、衣物、背景混入与高度过小。 |

所有 bbox 都会裁剪到 224 画布内，并通过 `ensure_bbox_size` 满足最小尺寸。关键语义缺失、bbox 为空或过小会成为明确 ROI 失败，不应以任意固定框静默替代。

### 6. 裁剪、resize 与脸颊拼接

对于 eye、lip、forehead、chin：

1. 用同一个 bbox 分别在对齐 RGB 和“final face mask 外已置黑的 RGB”上裁剪；
2. 若 `keep_aspect_ratio=true`，按最大可容纳比例缩放，居中贴到 224×224 黑色 canvas；
3. 记录 content 宽高、四边 padding、padding ratio 和 content ratio；否则才直接拉伸到 224×224。

对于 cheek：

1. 左右脸颊框分别从 raw 或 masked full image 裁剪；
2. 每个半区被直接 resize 到宽度 112、高度 224；
3. 左右半区水平拼接，得到 224×224 图像。

因此 cheek 的 `roi_resize_mode` 是 `pair_concat_fixed_half`，与其他 ROI 的 `keep_aspect_pad_canvas` 不同。后续代码不能把 cheek 当作普通单 bbox 的等比例裁剪，否则会改变输入定义。

### 7. 元数据、warning、成功矩阵与验收

每个 ID × ROI 都应记录至少以下内容：raw/masked 路径、bbox 坐标、ROI 成功状态、有效性、失败原因、warning 列表、canvas 内容尺寸与 padding、final mask 在 ROI 框内的比例、解析类别比例（skin、hair、background、neck、cloth、ear、eye、brow、nose、mouth、lip）。现有输出包括：

- `logs/roi_metadata.csv` / `roi_qc_metrics.csv`：逐 ROI 详细记录；
- `roi_success_matrix.csv`：逐 ID 的五 ROI 成功矩阵；
- `multi_roi_valid_ids.csv`：满足 core ROI 条件的可用样本；
- `failed_cases.csv`：全局或 ROI 失败；
- `sample_global_status.csv`：每例 Global 中间结果来源及状态；
- `qc_preview/`：随机成功、五 ROI 均成功、单 ROI 失败、padding 高及各 ROI 警告预览。

默认 warning 阈值仅标记，不自动排除样本：padding > 0.60、背景 > 0.20、衣物 > 0.05、颈部 > 0.05；另有 forehead hair > 0.30、cheek background > 0.15、eye nose > 0.10、chin neck > 0.10、chin cloth > 0.05 等区域特异阈值。

验收新生成版本时应断言：五个 ROI 目录的目标 ID 覆盖符合索引；每个成功 PNG 都是 224×224 RGB；raw/masked 路径、bbox 和 resize/padding 参数一致；masked 图在 global final face mask 外为黑；cheek 是左右固定半幅拼接；`multi_roi_valid_ids.csv` 与 success matrix 逻辑一致；所有失败和 warning 可追溯。任何更改 ROI 框比例、解析模型、global mask 参数、mask 定义、resize 方式或警告阈值，都必须记录为新的数据版本和新的输出目录。

## 四、RealFace 256×320 黑背景人脸图：从原图重新生成的方案 B

本版本用于新的 256×320 人脸实验输入，不是从既有 1024×1280 `aligned_srgb` 简单下采样得到，而是从原始高分辨率手机图像重新执行检测、关键点、几何对齐和语义解析。这样可以把滚转校正、4:5 裁剪和缩放一次性合成为 `原图 → 256×320` 的单次仿射重采样，避免 `原图 → 1024×1280 → 256×320` 带来的二次插值损失。该版本的核心目标是生成“去掉头发和背景，但保留主要五官”的黑背景人脸图。

### 1. 程序、配置与输出目录

| 项目 | 路径或说明 |
|---|---|
| 主程序 | `preprocessing/build_realface_256x320_blackbg_from_raw_v1.py` |
| 配置 | `config/preprocess/realface_256x320_blackbg_from_raw_v1.yaml` |
| 原始图像 | `data/processed/P0_Physics_Audit_v1/images/raw_scene` |
| 固定 500 例索引 | `data/processed/P0_Physics_Audit_v1/splits_500/nyha_3class_sex_stratified_group_5fold.csv` |
| pilot 输出目录 | `data/processed/global_face/realface_256x320_blackbg_from_raw_v1_pilot32` |
| 全量输出目录 | `data/processed/global_face/realface_256x320_blackbg_from_raw_v1` |

全量模式通过 `--full-500` 显式启用，写入 `full_output_dir`；默认仍是 pilot 模式，写入 `pilot_output_dir`。程序拒绝在未显式确认时覆盖既有输出目录，避免把 pilot 和 full 结果混在一起。

### 2. 为什么选择从原图重新生成

256×320 图像将作为新的正式实验输入，因此更关心目标分辨率下的图像质量和独立数据定义，而不是严格复刻已审核的 1024×1280 坐标。重新从原图生成有三个好处：

1. 几何变换只做一次：在原图坐标中计算 FaceMesh 几何，再把滚转、裁剪和平移缩放组合成一个 3×3 齐次矩阵，最终传给 `cv2.warpAffine` 的 2×3 矩阵。
2. 目标画布直接是 256×320：避免从 1024×1280 再下采样造成边界、五官和黑背景边缘的额外插值。
3. 数据版本更清楚：该目录下的 PNG、mask、metadata 和 QC 均属于 256×320 方案 B，不依赖 1024×1280 pilot 的文件存在与否。

### 3. 每个样本的处理流程

```text
固定 500 例索引
  → 从 raw_scene 按 ID 查找原始图像
  → 读取图像并应用 EXIF 方向校正
  → MediaPipe Face Detection 检测候选人脸
  → 按既有 224 管线的确定性规则选择主脸
  → 按上 10%、下 20%、左右各 20% 扩展主脸框
  → 在扩展框内运行 MediaPipe FaceMesh
  → 将 FaceMesh 关键点回映射到原图坐标
  → 根据双眼中心计算滚转角
  → 在滚转坐标系中按 face oval 和下巴构造 4:5 裁剪框
  → 组合滚转、裁剪平移和等比例缩放为一次性仿射矩阵
  → 从原图直接 warp 到 256×320 aligned_srgb
  → 对 aligned_srgb 运行 BiSeNet 解析
  → 构造方案 B face_valid_mask
  → aligned_srgb 在 face_valid_mask 外置黑
  → 保存最终 PNG、mask、解析标签、metadata、manifest 和 QC
```

几何上只允许画面内滚转校正和等比例缩放，不进行 3D 正面化、透视变换、横纵独立 resize、根据 mask 外接框二次裁剪或逐例人工调参。裁剪框只由 FaceMesh 几何决定，不由头发、皮肤 mask 或最终输出图决定。

### 4. 4:5 几何与输出尺寸

目标输出固定为：

```text
width = 256
height = 320
width:height = 4:5
```

配置中当前使用：

```yaml
geometry:
  output_width: 256
  output_height: 320
  side_margin_ratio: 0.03
  top_margin_ratio: 0.08
  bottom_margin_ratio: 0.025
  face_quantile_low: 0.02
  face_quantile_high: 0.98
```

实现上复用高分辨率真实人脸预处理中的 `face_geometry` 模块：先用左右眼中心计算滚转矩阵，再在滚转后的坐标系中用 face oval 的稳健分位数估计左右边界，用下巴和 bottom margin 锚定下边界，并在 top margin 不足时统一放大 crop width 与 crop height，保持 4:5 比例。最终矩阵的 2×2 线性部分必须是旋转加等比例缩放，不允许 shear 或独立横纵缩放；metadata 中记录 `affine_source_to_canvas`、`affine_canvas_to_source`、`uniform_scale`、crop 参数和奇异值。

### 5. 颜色与重采样策略

虽然最终保存的是普通 RGB uint8 PNG，本流程仍按 assumed sRGB 做颜色处理：

```text
uint8 RGB
  → float32 / 255
  → inverse sRGB
  → linear RGB float32
  → 使用最终仿射矩阵 warpAffine 到 256×320
  → sRGB encode
  → uint8 RGB PNG
```

正式几何重采样在 linear RGB 中完成，使用 `cv2.INTER_LINEAR` 和黑色常量边界。输出不会做自动白平衡、CLAHE、直方图均衡、曝光校正、每图 gamma 或 ImageNet 标准化。ImageNet mean/std 只在 BiSeNet 推理内部临时使用。

### 6. 方案 B 的 mask 语义

该版本的最终 mask 命名为 `face_valid_mask`，不是皮肤光学 1024×1280 版本中的 `skin_valid_mask`。二者含义不同：

- `skin_valid_mask`：只保留有效裸露皮肤，眼、眉、嘴唇、鼻孔等会被排除；
- `face_valid_mask`：保留常规人脸实验可能需要的主要五官，同时去掉头发、背景、耳、颈、衣物等。

方案 B 当前保留的 BiSeNet 类别为：

```text
skin, nose, left_brow, right_brow, left_eye, right_eye,
mouth, upper_lip, lower_lip
```

明确移除的类别为：

```text
eye_glasses, hair, left_ear, right_ear, earring,
neck, necklace, cloth, hat, background
```

最终规则为：

```text
face_valid_mask =
  keep_classes
  AND NOT remove_classes
  AND source_valid_mask
```

只做保守的小连通域删除，不做 alpha feather、不做额头补齐、不用椭圆 envelope 修复，也不根据 mask 外接框重新移动或放大人脸。最终 `images/<ID>.png` 是 `aligned_srgb` 在 `face_valid_mask == 0` 的区域严格置黑后的结果；mask 内像素与 `aligned_srgb` 对应位置完全一致。

### 7. 输出结构和用途

全量输出目录的核心结构为：

```text
realface_256x320_blackbg_from_raw_v1/
  images/
      <ID>.png                  # 最终方案 B 黑背景人脸图
  aligned_srgb/
      <ID>.png                  # 未置黑的 256×320 对齐 RGB
  face_valid_mask/
      <ID>.png                  # 0/255 二值方案 B mask
  source_valid_mask/
      <ID>.png                  # 原图有效来源区域
  parsing_label/
      <ID>.png                  # BiSeNet 原始整数标签
  metadata/
      <ID>.json
  manifests/
      realface_256x320_manifest.csv
  qc/
      preview_panels/
      pilot_contact_sheets/
      pilot_summary.csv
      qc_summary.json
  config/
      resolved_config.yaml
  full_ids.txt
  run_manifest.json
  COMPLETED.json
```

后续训练若需要“去头发背景但保留五官”的图像，应优先读取 `images/<ID>.png`。若需要重新定义 mask 或排查 parser 错误，应同时查看 `aligned_srgb/`、`face_valid_mask/` 和 `parsing_label/`。不要把 `face_valid_mask` 当作纯皮肤 mask 使用。

### 8. QC 图如何阅读

每例 QC panel 包含 10 个子图：

1. 原图 + 主脸检测框；
2. 原图 + FaceMesh + 4:5 crop；
3. 256×320 `aligned_srgb`；
4. aligned 图 + face oval/眼线/排除区轮廓；
5. BiSeNet `parsing_label` 可视化；
6. 方案 B 保留类别 overlay；
7. 被移除类别 overlay；
8. `face_valid_mask` overlay；
9. 最终黑背景图；
10. `source_valid_mask` 边界。

人工检查时最重要的是第 8 和第 9 个子图：第 8 个看 mask 是否正确保留五官、去掉头发背景；第 9 个看最终训练输入是否自然、是否有明显非人脸残留或过度挖空。

### 9. manifest、metadata、warning 与验收

`realface_256x320_manifest.csv` 保留原始 split CSV 的 ID、patient_group_id、fold、NYHA、性别和标签字段，并追加输出路径、预处理状态、失败代码和 warning。标签字段只用于追踪和后续切分，不参与人脸检测、裁剪、mask 或成功判定。

每例 metadata 至少记录：原图路径与尺寸、EXIF 是否应用、检测框、扩展框、FaceMesh 关键点派生几何、滚转角、crop 几何、仿射矩阵、输出尺寸、`face_valid_fraction`、`hair_fraction_in_face_region`、`source_valid_fraction`、warning 和 failure 信息。当前 warning 包括：`large_roll`、`source_boundary_visible`、`high_hair_occlusion`。warning 只用于 QC，不自动剔除或调参。

验收时应检查：

- `images/`、`face_valid_mask/`、`metadata/` 文件数与目标 ID 数一致；
- 成功 PNG 严格为 320×256×3 RGB；
- `face_valid_mask` 和 `source_valid_mask` 只包含 0/255；
- `face_valid_mask ⊆ source_valid_mask`；
- `images` 在 mask 外严格为黑色，mask 内与 `aligned_srgb` 一致；
- 被移除的 parser 类别不进入 `face_valid_mask`；
- 仿射矩阵为旋转 + 等比例缩放 + 平移；
- 单例失败不会中断整批处理；
- `COMPLETED.json` 只在 manifest、metadata、QC 和汇总完成后生成。

本版本已经在同一套配置下先完成 32 例 pilot，再生成固定 500 例全量数据；全量结果为 500/500 成功，warning 仅用于后续人工 QC 复查。

## 五、R3DPR SH93 重光照图：固定球谐光照 + CropPose 原相机

本节说明 Real-time 3D-aware Portrait Relighting（本文简称 R3DPR）生成 SH93 重光照图的实际实现思路。这里的“SH93 图”主要对应正式六重光照目录中的：

```text

```

该图使用 `examples/example_lightings.npy` 中第 93 组球谐光照（SH index 93），语义名称为 `neutral_front`。它不是普通 2D 滤镜，也不是在原始大图上直接逐像素调亮，而是先将原始照片中的人脸裁剪对齐并估计相机，再由 3D-aware relighting 模型重建人脸表示并用固定 SH93 重新渲染。


因此，如果只取 SH93 图，应读取 `relight_neutral_front.png`，不要从六张图中按位置硬取，最好按 `selected_names` 或文件名确认。

### 2. 每例 SH93 图的处理流程

对每一个病例，程序按以下顺序处理：

```text
读取 raw_scene 原图并应用 EXIF 方向校正
  → CropPose 检测人脸、裁剪对齐、估计该病例 original_camera
  → DPR 从 cropped_aligned 估计 original_sh
  → 使用 original_sh + original_camera 做一次原光照重建
  → 得到 reconstruction_original_light、planes、superres_ws
  → 复用同一 cropped_aligned、同一 original_camera、同一 planes
  → 用固定 SH93 渲染 relight_neutral_front.png
  → 保存图像、数组、逐例 metadata、全局 manifest 和 QC
```

关键实现点是：每例只运行一次 CropPose、一次 DPR、一次主编码；SH93 图不是重新跑一套完整编码得到的，而是在已有 `planes` 上替换光照向量后调用 `relighting.image_forward(..., gt_planes=planes, gt_superres_ws=...)` 渲染得到。这样可以保证同一病例的六套重光照共享同一身份/几何表征，主要变化来自 SH 光照。

### 3. CropPose 在这里的含义

R3DPR 中的 `CropPose` 不是简单裁剪函数，它同时承担三件事：

1. 在原始场景图中检测有效人脸；
2. 输出模型需要的对齐人脸输入 `cropped_aligned.png`；
3. 估计该原图对应的相机/姿态参数 `original_camera.npy`。

正式六重光照目录使用：

```text
camera_mode = original_cropose_camera
```

也就是每例 SH93 都使用该病例自己的 CropPose 原相机参数。这个版本不使用固定正视图相机，因此 `relight_neutral_front.png` 保留了每张原始照片估计得到的视角/姿态差异。

### 4. SH93 光照如何固定

程序从 `examples/example_lightings.npy` 读取 100 组 SH，整理为 `(100, 9)`，然后取第 93 行作为 `neutral_front`。当前 SH93 数值为：

```text
[0.8216134905815125,
 -0.12189235538244247,
  0.2680360972881317,
 -0.042181044816970825,
  0.0369199700653553,
  0.0356103852391243,
 -0.08398622274398804,
  0.006806450430303812,
 -0.03202999383211136]
```

这个固定 SH 会替换每例由 DPR 估计出的 `original_sh`，用于重新渲染统一光照版本。`original_sh` 仍会被估计，因为模型需要先用 `original_sh + original_camera` 做一次主重建，得到后续可复用的 `planes` 和 `superres_ws`。

### 5. 输出图像如何理解

正式六重光照版本中，每例至少有以下图像：

```text
original_input.png
cropped_aligned.png
reconstruction_original_light.png
relight_neutral_front.png
relight_left.png
relight_right.png
relight_top.png
relight_dim_front.png
relight_bright_front.png
```

其中 `relight_neutral_front.png` 才是正式 R3DPR SH93 图。它的含义是：

```text
同一病例的 cropped_aligned / original_camera / planes
+ 固定 SH93 neutral_front
→ R3DPR 生成的 512×512 重光照人脸图
```

它不是原始大图分辨率输出。当前已跑通模型输出实测为 512×512，因此若未来需要 1024×1024 文件，除非项目存在可用的 1024 原生生成权重或接口，否则通常只能采用 512 输出后的上采样或额外的高分辨率细节融合后处理。简单把原始高分辨率照片作为输入，不能绕过 CropPose/模型输出分辨率限制直接得到原生 1024 重光照图。

### 6. 与早期单 SH93 输出目录的区别

早期单 SH93 程序 `run_batch_example_sh093_fixedlight_500.py` 输出到：

```text
data/processed/P2_ExampleSH093_FixedLight_v1
```

该目录每例有三类图：

```text
images/original/<case_id>.png
images/fixedSH_origcam/<case_id>.png
images/fixedSH_fixedcam/<case_id>.png
```

这里的 `fixedSH_origcam` 与正式 `relight_neutral_front.png` 思路接近，都是固定 SH93 + 每例 CropPose 原相机；而 `fixedSH_fixedcam` 是固定 SH93 + 全局固定正视图相机，使用 `yaw=0, pitch=0, roll=0, radius=2.7, focal_length=18.837`。后续训练或分析若强调“保留原图估计视角”，应优先使用正式六重光照目录下的 `relight_neutral_front.png`，不要误用 `fixedSH_fixedcam`。

### 7. 运行状态和质量边界

正式六重光照版本已经完成固定 500 例：

```text
total_available_inputs = 500
selected_inputs = 500
available_success_output_count = 500
failure_count = 0
relight_count_per_case = 6
device = cuda
```

每例保存 `estimated_original_sh.npy`、`original_camera.npy`、`planes_shape.npy` 和 `selected_six_sh_casecopy.npy`。逐例 metadata 中记录 `crop_pose_runs=1`、`dpr_lighting_estimation_runs=1`、`full_face_encoding_runs=1`、`used_same_planes_for_all_six_relights=true`，用于审计实现是否符合“同一病例六套重光照复用同一表征”的要求。

CropPose 检测采用保守 fallback：官方阈值 `0.95` 失败时，依次尝试 `0.90` 和 `0.80`。fallback 只影响人脸是否能被检测裁剪，不改变模型权重，也不引入标签信息。失败病例会记录到 `failure_cases.csv` 并继续后续病例；当前正式结果为 0 失败。

### 8. 对后续分析的结论

1. R3DPR SH93 图主要适合作为“统一光照后的生成式人脸表征输入”，用于降低原始拍摄光照差异对训练的影响。
2. 它不是无损物理校正图，也不是原图像素级 relighting；人脸细节、边界和肤色会受到 CropPose 裁剪、模型重建和生成器先验影响。
3. `relight_neutral_front.png` 保留每例原相机视角，因此它统一的是光照 SH，不统一头部姿态。如果研究目标需要同时统一姿态，应使用或另建 fixed-camera 版本，并明确记录为不同数据定义。
4. SH93 的“neutral_front”来自经验筛选的 example lighting，而不是由每例真实环境光反演出的绝对标准光源。它更适合做相对一致化输入，不宜解释为严格物理测量的标准正面照明。
5. 由于输出是模型生成的 512×512 人脸图，后续模型训练若输入更高分辨率，应先判断是否真的需要 1024；上采样只改变文件尺寸，不增加真实生成细节。
6. R3DPR 处理全程不使用 NYHA、fold、预测结果或分类标签参与像素计算；本阶段也未进行分类训练、五折实验或模型权重修改。因此它应被归类为独立的数据预处理/生成阶段，而不是训练阶段的一部分。
